# Приглашения, приветствия и статистика LazyBot

Первая часть замены Invite Tracker для одного сервера Lazy Dice. Голосовые комнаты работают по прежним правилам. Учёт приглашений по умолчанию выключен: подготовьте разрешения, затем включите модуль.

## Включение на Botkeep

1. Проверьте код через `npm run verify`, затем сделайте **Commit and Push** в WebStorm. Для подготовленного локального Node.js используйте команду терминала из README.
2. Откройте [Discord Developer Portal → LazyBot → Bot](https://discord.com/developers/applications/1565018164020912238/bot). Включите **Server Members Intent** и сохраните. **Message Content Intent** и **Presence Intent** не нужны.
3. В Discord дайте роли **LazyBot** серверное право **«Управлять сервером»**: оно нужно для счётчиков приглашений. Разрешите просмотр каналов, к которым относятся используемые ссылки. Права голосовых комнат сохраняются; право «Администратор» не требуется.
4. Подготовьте постоянный текстовый канал приветствий и закрытый канал журнала, например `#приветствия` и `#журнал-участников`. Разрешите LazyBot просмотр и отправку сообщений в них. Обычным участникам закройте просмотр журнала средствами Discord: бот не меняет эти права автоматически.
5. В Botkeep остановите процесс и скачайте резервную копию `data/`, если модуль уже использовался. Обновите исходники через **GitHub → Merge files → Sync repository**. Дождитесь нового коммита и времени синхронизации.
6. В **Environment / Среда** сохраните `COMMUNITY_ENABLED=true`. Три существующие переменные DISCORD_TOKEN, DISCORD_GUILD_ID и DISCORD_CATEGORY_ID сохраняются. Путь базы по умолчанию — `data/lazybot.sqlite`; задавать COMMUNITY_DATABASE_PATH необязательно.
7. Запустите **Start**. В Console должно появиться сообщение о регистрации команд сообщества. Первый запуск создаст базу и начальную резервную копию.
8. В Discord выполните `/setup`, выбрав `welcome_channel` и `log_channel`. При необходимости выберите `leave_channel`. Затем выполните `/welcome-test`.

Если команды не появляются, проверьте Console и установку приложения со scopes `bot` и `applications.commands`. Для повторной авторизации можно использовать [ссылку с командами](https://discord.com/oauth2/authorize?client_id=1565018164020912238&scope=bot%20applications.commands&permissions=1024&integration_type=0); остальные права настраиваются отдельно.

Токен в команды и сообщения не вставляется. Если он попал на скриншот, сбросьте его в Developer Portal и замените сохранённые значения.

## Команды

Ответы команд приватные: их видит только вызвавший участник. Приветствия и журнал отправляются в выбранные текстовые каналы.

| Команда | Назначение |
| --- | --- |
| `/setup` | Настройки и состояние учёта приглашений |
| `/setup welcome_channel:#приветствия log_channel:#журнал-участников` | Выбрать каналы |
| `/setup leave_channel:#выходы` | Включить отдельные сообщения о выходе |
| `/setup disable_welcome:true` | Отключить приветствия; аналогично disable_leave и disable_log |
| `/setup welcome_text:…` | Изменить шаблон |
| `/welcome-test` | Отправить приветствие для себя без записи входа в статистику |
| `/invites user:@участник` | Уникальные приглашённые: всего, остались, ушли и ещё проверяются |
| `/inviter user:@участник` | Источник последнего записанного входа |
| `/top invites period:…` | 10 лучших приглашающих |
| `/stats period:…` | Входы, выходы, повторные входы, возраст аккаунтов и источники |
| `/invite-label set code:… label:Друзья` | Назвать существующую ссылку |
| `/invite-label remove code:…` | Убрать метку |
| `/invite-label list` | Показать метки |

В `user` по умолчанию используется вызвавший команду участник. Периоды: последние 24 часа, 7 дней, 30 дней или всё время. Это скользящие интервалы, не календарные месяцы.

Настройки, метки и тест приветствия требуют **«Управлять сервером»**. Проверка выполняется в обработчике, даже если доступ к командам изменён через интеграции Discord. Остальные команды доступны участникам сервера. Метки применяются к будущим входам: история сохраняет название источника на момент события.

## Шаблон приветствия

Пример для параметра welcome_text команды `/setup`:

```text
Привет, {member}! Добро пожаловать на {server}! Правила — в #правила. Пригласил: {inviter}. Нас уже {count}!
```

Для кликабельной ссылки на правила вставьте упоминание нужного канала через Discord вместо обычного текста `#правила`.

| Переменная | Значение |
| --- | --- |
| `{member}` | Упоминание нового участника |
| `{server}` | Название сервера |
| `{inviter}` | Упоминание пригласившего либо «неизвестно» |
| `{source}` | Метка, код ссылки или описание неизвестного источника |
| `{count}` | Число участников сервера, включая ботов |

Шаблон — от 1 до 1200 символов. Неизвестные переменные отклоняются до сохранения. В приветствии разрешено уведомление только новичка. Пригласивший, роли и everyone показываются без уведомления; команды и журнал никого не уведомляют.

## Правила подсчёта

- Каждый человек даёт не больше одного приглашения: при первом записанном входе с известным пригласившим. Повторный вход, даже по другой ссылке, не добавляет балл.
- В `/invites` «остались» относится к людям, впервые пришедшим от указанного пригласившего. После возвращения человек снова считается оставшимся у первоначального пригласившего.
- `/inviter` показывает источник последнего наблюдавшегося входа: при возвращении он может отличаться от первоначального пригласившего.
- Неизвестный первый вход не получает балл задним числом при повторном входе. Боты и само-приглашения не дают баллов.
- Аккаунты младше 7 дней отмечаются отдельно, без штрафа и без утверждения, что они поддельные.
- В `/stats` считаются события: возвращения входят в общее число входов. Боты исключены. «Разница» — наблюдавшиеся входы минус выходы, не полная численность сервера.
- Учёт начинается после включения. Старые события и базу Invite Tracker LazyBot автоматически не импортирует.

## Неизвестные источники и разрывы связи

Входы объединяются в короткие пачки, счётчики запрашиваются последовательно. Если счётчик ровно одной ссылки увеличился на число вошедших людей, входы относятся к этой ссылке.

Разные использованные ссылки, несовпадающие счётчики, пропавшие права, исчезнувшие одноразовые ссылки и новая уже использованная ссылка остаются неизвестными. Общая ссылка сервера (vanity) учитывается отдельно, без вымышленного пригласившего.

Это сопоставление по доступным данным Discord, а не гарантия определения каждого входа. Во время остановки и потери связи возможны пропуски. Старые счётчики после перезапуска не используются для начисления пропущенных приглашений.

После запуска/переподключения бот проверяет присутствие уже известных участников. Пока проверка идёт, `/invites` показывает их отдельно как непроверенных. Незамеченный выход может обновить присутствие, но не создаёт событие с выдуманным временем. Исторические приглашения сохраняются.

Ошибка отправки приветствия не удаляет записанное событие. Проверьте `/setup`, разрешения канала и Console. Массовой повторной рассылки нет.

## Данные и резервные копии

SQLite встроена в Node.js 24.17+: отдельный сервер базы и платный сервис не нужны. Сохраняются ID, времена входов/выходов, пригласившие, коды и метки ссылок, признаки повторного входа и молодого аккаунта, настройки. Переписки и звук не записываются.

База по умолчанию — `data/lazybot.sqlite`. При работе рядом могут находиться файлы `lazybot.sqlite-wal` и `lazybot.sqlite-shm`. Согласованные резервные копии — в `data/backups/lazybot-YYYY-MM-DD.sqlite`.

`data/` и SQLite исключены из Git. Хостинг должен сохранять папку при перезапуске: это проверяется реальным перезапуском до удаления Invite Tracker. Обновляйте через **Merge files**. **Replace files**, пересоздание сервера или удаление `data/` могут уничтожить историю и настройки.

Автоматическая копия создаётся при запуске, затем раз в 24 часа: не более одной за дату UTC. Хранятся последние 7 копий по датам. Копии на том же сервере не заменяют скачанную независимую копию.

Перед обновлением можно создать свежую копию локально:

```powershell
$env:Path = "$PWD\.runtime;$env:Path"
.\.runtime\npm.cmd run backup
```

На хостинге с Node.js 24 — `npm run backup`, если доступен терминал команд, либо успешная резервная копия панели Botkeep. Скачивайте копии через Files/SFTP из `data/backups/`. Нельзя копировать только основной файл работающей базы: изменения могут оставаться в WAL.

Восстановление: остановите бота, сохраните всю текущую `data/` отдельно, замените основной файл согласованной копией и уберите старые одноимённые WAL/SHM. Затем запустите бота. Исходную резервную копию держите вне заменяемой папки. Более старый код не открывает базу с неизвестной новой версией схемы.

Отдельной команды удаления персональной истории в первой версии нет. База содержит сведения об участниках: не публикуйте её в GitHub или открытых каналах. Очистка данных согласуется с владельцем сервера при остановленном модуле.

## Проверка перед заменой Invite Tracker

1. `/setup` показывает работающий учёт; `/welcome-test` отправляет правильное сообщение в выбранный канал.
2. Друг входит по известной ссылке: одно приветствие и запись журнала, ожидаемые `/inviter` и `/invites`.
3. Друг выходит и возвращается: входы растут, уникальные приглашения не удваиваются, «остались» восстанавливается.
4. При одновременных входах по разным ссылкам неоднозначные источники остаются неизвестными.
5. Перезапуск Botkeep сохраняет настройки, метки и статистику; новые входы продолжают учитываться.
6. Голосовые комнаты работают как раньше, постоянное «Лобби» сохраняется.
7. Скачайте резервную копию. После проверок можно отключать дублирующие приветствия Invite Tracker или удалять его с сервера.

Для возврата к режиму голосовых комнат задайте `COMMUNITY_ENABLED=false` и перезапустите. База остаётся на диске. Зарегистрированные команды могут остаться в меню Discord, но выключенный модуль на них не отвечает.

## Где смотреть код

- `src/community.js` — события Discord, запись истории и отправка сообщений.
- `src/invite-tracker.js` — очередь, сравнение счётчиков и восстановление после ошибок.
- `src/community-store.js` — SQLite, настройки и статистика.
- `src/community-commands.js` — команды, права и ответы.
- `src/community-messages.js` — шаблоны и упоминания.
- `test/community-*.test.js` и `test/invite-tracker.test.js` — проверки без настоящего Discord.
